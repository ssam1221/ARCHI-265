System Overview

TimeGrapher is a real-time acoustic watch-timing instrument. It captures the ticks of a mechanical watch (from a microphone, a recorded WAV file, or a synthetic generator), runs them through a streaming DSP + detection core, and displays beat rate, rate error, beat error, and amplitude — both as plots and as a folded "sound image".

UI / Orchestration

MainWindow (QMainWindow) is the single conductor: owns threads, the detection context, analytics state, and all widgets.

Producers (3 threads)

TAudioWorker, TPlaybackWorker, TSimWorker each fill one shared ring buffer and signal the GUI thread.

Shared Buffer

TMasterAudioDataRaw — a mutex-guarded float ring buffer (30 s) bridging producer threads and the GUI thread.

Detection Core (C)

libtimegrapher (tg_* API) chains HPF → envelope → onset detector → BPH/PLL sync, emitting A/C events.

Visualization

SoundImageRenderer folds PCM into beat-period columns; QCustomPlot draws the scope & rate plots.

Analytics & Utilities

RollingLeastSquares / RollingAverage smooth rate, beat-error and amplitude; WavStreamWriter records sessions.

Architectural Layers

The codebase splits cleanly into 8 responsibilities. The C detection/synthesis core is deliberately decoupled from Qt (pure C with extern "C"), so it is portable and testable.

Boundary worth noting: the only data shared across the thread boundary is TMasterAudioDataRaw. Workers write samples + counters under a mutex and emit a Qt signal; the GUI thread reads the delta and does all processing, plotting, and analytics. The detection core itself is single-threaded and lives entirely on the GUI thread.

Three interchangeable producer threads, one shared buffer, and the Qt GUI thread as the sole consumer. Cross-thread communication is via queued signal/slot connections; data hand-off is via a mutex-protected ring buffer.

Detection Core Pipeline (tg_process)

The pure-C libtimegrapher processes float32 mono PCM through a fixed streaming chain. tg_context_t composes one instance of each stage and carries the delay line that aligns the emitted envelope with the detected events.

1 · DC blocker — tg_hpf_t

Single-pole high-pass (~200 Hz) rejects rumble/hum. No band-pass (would smear A & C).

2 · Envelope — tg_envelope_t

Full-wave rectify + 0.15 ms one-pole LPF; keeps A & C as distinct peaks.

3 · Detector — tg_detector_t

Silence-based onset state machine → A (onset) and C (peak) raw events with sub-sample timing; V5.6 regime-change reset.

4 · BPH + Sync — tg_sync_t / Bph

Rayleigh phase-score picks the beat period from a candidate list; a PLL tracks period & A→C offset.

Runtime Data Flow (Live Capture → Display)

One full cycle from a buffer of microphone samples to updated plots and readouts. The producer/consumer split is the queued AudioDataReady signal.
