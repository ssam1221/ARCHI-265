요약 — SafePlant Manufacturing 사례 연구 실습

한 줄 요약 노후화된(2010년) "전량 클라우드 전송" 공장 모니터링 시스템을, 엣지 지능 기반 차세대 시스템으로 재설계하는 45분 팀 아키텍처 설계 과제. 핵심 긴장 관계는 실시간 안전·예측 정비 ↔ 불안정한 네트워크·데이터 프라이버시·클라우드 비용 절감이다.

상황 (Context)

  • 현재 문제: 모든 원시 센서 데이터를 클라우드로 스트리밍 → 비용 과다, 단순 임계값 기반 탐지(예측 불가), 종이·달력 기반 예방 정비.
  • 규모: 펌프 500, 공작기계 200, 화학 탱크 50, 보안 카메라 100. 센서 샘플링 평균 10Hz.
  • 네트워크: 공장 현장은 HaLow WiFi 5Mbps, 가용성 약 85%(중단 빈번) → 오프라인 동작 필수.

반드시 충족할 핵심 요구사항

  1. 실시간 이상/위험 상황 탐지 (안전)
  2. 예측 정비 (고장 사전 탐지)
  3. 런타임 중 탐지·예측 정확도 개선
  4. 24×7 운영 + 네트워크 중단 중에도 지속
  5. 민감한 원시 데이터 보호
  6. 정비 보고서 자동 생성 (버튼식)
  7. 내·외부 기술자용 보안 상태 페이지(분석 포함)
  8. 클라우드 비용 최소화
  9. 센서 노드 OTA 업데이트
  10. 확장성(새 기계 센서 손쉬운 추가)

핵심 제약 조건

영역핵심 내용
장치 등급A: M33 $10 / B: A53 2GB $150 / C: Jetson Orin NX 8GB $750 — 이 셋만 사용
프라이버시원시 운영 데이터 공장 밖 반출 금지. 익명화 데이터(집계 통계·모델 가중치·특징 벡터)만 전송 가능. 식별 정보(fingerprint) 반출 불가

센서 종류진동 / 온·습도 / 음향 / 가스·연기 / 기계 작동 상태

설계 시 답해야 할 5가지 (힌트)

  1. 시스템 토폴로지: 서버·센서·중간 노드 배치와 분할 근거.
  2. 연결성 전략: 최악의 중단 시 반드시 동작해야 할 기능과 장애 내성 설계.
  3. 모델 전략 & 지능 배치: 모델 유형·역할·위치·학습 방법, 업데이트 시점 판단 및 실패 배포 관리.
  4. 데이터 관리: 엣지/운영센터/클라우드 데이터 분배, 학습 데이터 저장 위치, 보안(프라이버시·비용·대역폭).
  5. 확장성: 아래 품질 속성 시나리오 충족.

확장성 시나리오 새 기계에 센서 노드 12개를 부착 → 기존 인프라/네트워크에서, 다운타임 0, 3일 이내에 부착·보정·통합 완료.

그 밖의 설계 동인

  • 기존 시스템 개발 비용 최소화
  • 시스템 지연 시간 최소화
  • 실시간 탐지 오탐(false positive) 최소화 → 센서 정확도 극대화
  • 예측 정비 정확도 극대화

출제 의도 핵심 포인트

"정답은 없다 — 아키텍처 결정·근거·트레이드오프를 논하라." 사실상 다음을 요구하는 설계 문제다: 비용·프라이버시·네트워크 불안정 때문에 지능을 클라우드에서 엣지(센서 노드 + 온프레미스 서버)로 이동시키되, 클라우드는 무거운 학습·대형 모델 역할로 한정하는 3계층(엣지–온프레미스–클라우드) 하이브리드 구조를 어떻게 구성할 것인가.
